## 2. 资源导入与路径

1. 从检查目录复制33个WAV到`assets/audio/`，文件名保持不变。已有同名文件先比较哈希、保留可恢复副本；不要把旧12项覆盖回新版。
2. 保留项目当前已有的菜单音乐、游戏BGM、menu_click.wav、card_choice.wav、menu_entry_whoosh.wav、chase_transition.wav、chase_heartbeat.wav。这33项不替代它们。
3. 引擎资源路径从资源根下一层开始。例如物理文件`assets/audio/swarm_hit.wav`，加载字符串为`audio/swarm_hit.wav`，不要写`assets/audio/...`。
4. 不需要为了接入而转成OGG。实际加载失败时再依据引擎日志定位，不凭扩展名猜测。

### 3.1 关键：当前事件会在模拟步内清空

`SwarmWorld:Emit()`只把事件追加到`world.events`，它不会自动发送到EventBus。`SimState:Tick()`调用`ConsumeEvents()`，该函数处理后执行`self.world.events={}`。因此，帧末的`GameAudio:Update()`再读取`world.events`会漏掉事件，一个渲染帧还可能运行多个模拟步。

建议在`ConsumeEvents()`清空之前，把音频需要的事件转为独立批次，经新增EventBus事件（例如`audio:world_events`）发送给表现层。该事件名是本方案新增，当前项目尚未实现。GameAudio只入队，在帧级统一合并、按优先级播放，不要改写、清空或抢先消费原事件列表。保留教程和进化系统的消费流程。

转发时补齐位置、发生时控制群、开关变化等必要快照，不能保留整个可变world引用作为事件内容。批次携带运行实例标识与递增序号，重开丢弃旧批次。world有些事件仅含cellId或swarmId，需在实体仍可查到时解析位置。

卡牌获得用已有EventBus的`cards:acquired`作为唯一入口；world中的`card_acquired`不再重复播放。结局用`sim:ending`或ending状态上升沿二选一，不同时触发。

### 3.2 结局与重开的顺序

当前`GameAudio:Update()`先处理`sim.ending`，之后才检查world是否更换。现有`ResetChase()`也同时重置结局状态。接入时把“绑定新运行／清队列”和“追逐重置”职责理清：先识别新world、清旧音效与状态，再处理当前运行结局，避免旧局endingActive让新局失败声漏播。

事件队列在整帧末裁决：该帧最终进入失败时，失败提示优先，并抑制同帧普通受击和群体覆灭，避免结局三重叠音。

## 5. 技能事件还需补齐的信息

当前`skill_used`只有cardId、swarmId、requestId，无法区分集合／留守和部分开关前后状态。建议在权威成功路径增加不改变规则的表现载荷：command、activeBefore、activeAfter、cellId及必要位置，或者发射独立状态事件。不要解析中文提示字符串来识别成功或技能类别。

- 锚定会因主动移动解除，也会因冲刺、藏身、分裂等改变。监听实际状态变化；同一帧从开到关要有明确事件顺序或只保留最终有效变化，避免双响。
- 隐藏退出已有`hide_exit`，主动node_hide退出也会发射它，所以不能再在skill_used上额外播放退出声。
- 伪装目前直接更新`camouflaged`，没有专门形成事件。可在该值false→true时新增表现事件；每帧检查为true不能重复触发。重开和首次绑定只建立基线，不制造虚假形成声。
- 同一模拟步内变化可能发生又撤销，若要求完整反馈应在变化点记事件，不能只依靠帧末状态比较。
- `skill_failed`当前主要覆盖接管预约取消，不能假定所有失败都会发它。主动失败应在统一操作入口报告一次；异步预约取消可给一次轻提示，但静默状态刷新不播错误。
- 控制切换可能在播放前已改变当前群，受击判断使用事件发生时的控制群快照，避免把原控制群受击漏掉。

## 6. 播放器、混音与环境音

### 声源与分类

32项单次音效使用`SOUND_EFFECT`，环境音使用`SOUND_AMBIENT`，保留原有BGM和追逐层的`SOUND_MUSIC`分类。`UserSettings:ApplyAudio()`已经统一控制这些类别，不要再手动乘一遍effects或ambient百分比，避免音量平方衰减。

资源初始化时缓存，每个单次Sound设为不循环。环境Sound设循环，独立声源持有。复用声源时明确用`source:Play(sound, 0, gain)`，0表示素材原采样率；不能把1、0.95等倍率直接作为frequency传入，它的单位是Hz。引擎依据见`engine-docs/api/audio.md`。

采用固定容量声源池，例如8个常规声源、2个重要提示声源、1个失败结算声源，以及1个环境声源。这是实现建议，不是引擎强制数量。不要每个实体每帧创建节点或声源；池满优先丢弃远处释放、吸收等低优先事件，保留受击、挡击、断尾和失败。

首版可用普通SoundSource并按事件位置计算距离衰减；缺少位置时从事件快照补齐，不能全部当作屏幕中心。无需为了本次接入新增3D监听器系统。屏外常规繁殖、死亡事件可省略；节点危险提示即便远处也保留一个低音量提醒，限制全局密度。

### 环境循环生命周期

- 成功进入游戏后，以约0.8秒淡入一个micro_ambience循环实例；不每帧重新Play，不每次切群重启。
- 普通暂停、选卡或教程暂停可缓慢降到正常gain的约35%，恢复时平滑升回；不要暂停一帧就Stop并从头播放。
- 返回菜单时约0.3秒淡出并停止；开始新局不叠加旧实例。
- 胜利时随已有1.8秒游戏音频淡出归零，影片开始前停止，避免环境声污染影片。
- 失败时约0.4秒淡出环境、BGM和追逐层，但让1.8秒ending_defeat完整播放。
- 退出／销毁时停止全部声源并取消EventBus订阅。场景仍由GameAudio对象持有，沿用当前生命周期约束。

### 结局提示不要被现有淡出截断

当前结局分支收集旧声源并在失败后0.4秒停播。新增环境和普通音效池需要纳入背景淡出；**专用ending_defeat声源不能加入这个0.4秒停止列表**。否则新失败声会在1.8秒播放完前被切断。胜利不播放失败声，保留现有影片音量控制。

失败后留在结算页面时允许完整音尾；用户主动重开、返回菜单或退出时停止旧局提示，不要求强行听完。

### 限频与叠加

先按批次和实体合并，再按全局间隔过滤。吸收20颗不能同时播放20个virus_absorb；节点警告由多个免疫单位同时触发也只给清楚的一次提醒。同一攻击的shielded真假分支只播一种，尾部群体覆灭与整局失败也做互斥优先。

若同时使用合并播种或破裂散播，复用组合：ability_released的kind=merge_seed用轻量skill_decoy，kind=rupture用轻量release_batch；与同批merge或cell_dead合成一组，别全音量叠加。感染拖尾高频投放可先静音，或极低gain且限频，不能每颗必响。

## 7. 接入实施顺序

1. 导入资源，建立配置与预加载，缺失文件只日志一次并安全跳过，不影响玩法。
2. 先实现按运行标识管理的事件桥、队列与声源池；确认多模拟步不会漏播或重播。
3. 接入12项核心音效，优先验证空吸附、操作失败、卡牌去重、结局淡出。
4. 接入10项优先补充，再接开关、调度和伪装事件；补齐必要载荷。
5. 接入环境循环，验证用户音量分类、暂停、重开与影片衔接。
6. 调整各gain、距离衰减、同帧优先级与限频，完成下面验收。

本项目本地预览按项目AGENTS与taptap-maker-local工作流执行。实际代码／资源修改批次后检查预览状态：仅当process_alive=true才刷新并取日志／证据；已停止或未验证会话不自动启动。本任务不需要远端构建、提交或推送。

## 8. 实机验收清单

- 资源：33项加载无错误，环境正确循环；短音效不意外循环，播放无明显变调。
- 基础操作：合法空吸附有脉冲；冷却中按E只给一次拒绝；分裂失败不播放成功声；切群成功一次一响。
- 感染与产出：感染完成一次；同一感染的独立感染附加事件不双响；成批释放不按颗数炸音。
- 免疫：真实killed>0才受击；挡击不同时受伤；节点预警被取消后不补播过期声音。
- 技能：未获得、冷却、质量不足、非法目标都不播成功；预约接管不提前播形成声；最终产出组群才播接管。
- 开关：锚定开关方向正确，自动解除不双响；藏身进出各一次；伪装静止保持时不反复响。
- 卡牌：打开用旧展示声，确认获得用新声音，各自仅一次；被动扩容不持续发声。
- 密集场景：大量细胞释放或多个群合并时，提示仍可辨识，声源数量有上限，帧率无明显退化。
- 环境：连续循环至少三遍，耳机和手机各试听一次，无接缝、抽动、过强气泡；BGM下重要提示清楚。
- 设置：effects=0时新增单次声音静音；ambient=0只关闭环境；master=0全部静音；不重复乘分类音量。
- 结局：失败音完整1.8秒，背景按约0.4秒退出；胜利保留影片音频，环境不叠加。主动离开结算停止旧声。
- 重开：失败后马上重开再失败也能正常播放；队列、去重ID、声源与环境均不串局。
