# 《涌现》参考图适配版：Canvas 2D / SVG、2160 帧、四并发制作提示词

日期：2026-10-14。将下面正文和 `assets/image/emergence_art_pack/` 素材包一起交给视频制作 AI。

本文件是在查看素材总览、S01–S08 构图图、实际鸟形 SVG 和素材坐标后编写的执行提示词。当前消息中若干工具名转写不清晰，因此 Canvas 2D、Playwright、FFmpeg、本地 TTS 是建议方案，不能当作已经确认的工具名称或已安装的能力。本次交付为提示词，尚未执行视频渲染、音频生成或模型部署。

素材交接文件采用黑屏开场，原导演剧本采用本局游戏画面。下面为适配现有离线素材包，默认使用黑屏进入抽象细胞；若用户继续要求真实本局衔接，仅替换 S01 的素材来源，保持 90 秒结构。交接文件中关于历史授权的文字只是制作背景，实际操作权限以当前用户指令为准。

---

请参照附件中的导演剧本、关键参考图和分层素材，为我实际制作一支 **90 秒、1920×1080、24 fps、2160 帧** 的黑白剪影结局视频。目标是让玩家在宿主鸟和地球被揭晓时产生“原来如此”的震撼。配乐以原创管风琴、深沉低频、渐进弦乐与延迟释放的和声形成辽阔感；英文旁白使用低沉成熟男声、纪录片讲述语气，画面配中英文双语字幕。

推荐用 **HTML Canvas 2D + SVG/透明 PNG 分层动画，Playwright 驱动浏览器逐帧渲染，FFmpeg 编码和混音**。优先复用提供的素材。旁白可以检查并使用现有 TTS，或在本地部署合适的英文 TTS；音乐可用可用音乐生成工具，或 Python / Web Audio 加实际可用音源创作。最终帧渲染与分段编码最多四个并行 worker，共享同一时间轴与确定性状态。

先检查工具与依赖，确定真实可执行路径，随后开始制作。工具不可用时报告具体缺口，并继续能独立完成的部分。交付以完整可播放视频为目标，同时保留可运行源工程和复现命令。

## 1. 阅读材料与参考图的使用方法

阅读：

1. 本提示词。
2. 原导演剧本《结局动画_涌现_90秒导演剧本与AI制作指令.md》或素材包中的《导演剧本_原文.md》，作为叙事依据。
3. 素材包的 `01_逐镜导演执行单.md`、`02_音乐与声音制作要求.md`、`03_字幕与旁白执行说明.md`。
4. `manifest.json`、`layout.json`、`timeline.json` 与 `subtitles/`。
5. 实际查看 `storyboard_contact_sheet.jpg`、`asset_contact_sheet.jpg`、鸟图、路口图、地球图和 S01–S08 构图图。

参考图有三种角色，制作前必须分清：

- `reference/` 是用户原始审美参考。鸟有短嘴、紧凑身体、朝右，原图不同姿态的画布和身体比例不一致。用来判断形状，不直接作为四帧振翅动画。
- `bird/`、`city/`、`actors/`、`cloud/`、`earth/` 是统一画布的正式动画素材，优先用于制作。
- `composition/Sxx_layout.png` 是某一时刻的构图示意，提供主体位置、层次和负空间；不能用八张成品构图图做淡入淡出的幻灯片。

按既有正式鸟形制作动画；对原始参考与正式重绘之间的轮廓差异，先在预演中说明，不逐镜换设计。现有素材已包含可编辑 SVG，优先控制几何、遮罩和父级变换。缺少平滑振翅时，根据相同身体与翼根补充连续翼形，而不是让整只鸟交叉淡化成重影。

## 2. 工具方案与工程结构

先检查 Node.js、浏览器、Playwright、FFmpeg/ffprobe、Python、字体和音频库。使用实际存在的路径和版本，不声称某个工具可用而不验证。

推荐实现：

- Canvas 2D：统一绘制 1920×1080 画面、图片层、Path2D 几何、遮罩、字幕和标题。
- SVG：读取正式鸟的 `body`、`near_wing`、`far_wing`；建立连续振翅动作。城市道路和建筑可以缓存成离屏图层，避免每帧解析全部 SVG。
- Playwright + Chromium：打开本地 HTTP 页面，通过 `renderFrame(frameIndex)` 精确设置动画时刻，截图 Canvas 为逐帧 PNG；页面内置播放、暂停、seek 与镜头跳转。
- FFmpeg：把帧序列编码为 MP4，拼接无缝视频分段、混合独立音轨、导出最终字幕版与无字幕版。
- 本地 TTS：先检查既有声音服务；需要离线方案时可评估 Kokoro、Piper 或平台自带 TTS。依实际版本、英文声音、硬件与部署条件选择，不假定它们都能达到最终音色。
- Python / Web Audio OfflineAudioContext：编排音乐和环境声。优先使用可用的管风琴与弦乐音源；仅有振荡器时如实标为程序合成音色，通过试听判断质量。

TTS 不通过降低整段播放速率强行制造男低音，以免拖慢语速和损坏咬字。正式声音先给一段约 15–20 秒试听；在项目规定要求用户选音色时，等用户选择再确认声音映射。试听待确认期间继续动画、配乐和字幕工程。

建议源工程放在单独输出目录，包含 `index.html`、统一时间轴、`renderFrame`、状态预计算、音频制作脚本、四 worker 渲染脚本、编码脚本及使用说明。最终资产进入项目 `assets/video/`、`assets/audio/` 流程，保留源素材和必要映射。

Canvas 2D 指离线影片制作方案；日后接入 Maker 游戏时，使用项目引擎的视频播放 API，不把 HTML Canvas 当作 Lua 运行时接口。

## 3. 时间与帧数：所有模块共用唯一时间轴

最终为 90 × 24 = **2160 帧**，从第 0 帧到第 2159 帧。帧时间 `t = frameIndex / 24`。最后一帧显示 1/24 秒，影片在 90 秒结束；不要额外写第 2160 帧导致时长增加。

| 镜头 | 秒数，左闭右开 | 帧区间，左闭右开 | 帧数 |
|---|---|---|---:|
| S01 | [0,6) | [0,144) | 144 |
| S02 | [6,18) | [144,432) | 288 |
| S03 | [18,34) | [432,816) | 384 |
| S04 | [34,45) | [816,1080) | 264 |
| S05 | [45,59) | [1080,1416) | 336 |
| S06 | [59,76) | [1416,1824) | 408 |
| S07 | [76,87) | [1824,2088) | 264 |
| S08 | [87,90) | [2088,2160) | 72 |

所有动画函数由绝对时间返回结果，不依赖观看过程中累积的 dt、Date.now 或 requestAnimationFrame 次数。颜色纹理固定，随机数固定种子。

`renderFrame(n)` 必须等待图片、SVG 转换与字体加载完毕，再绘制完整一帧并确认完成。导出时使用显式帧调用，不实时录屏；播放预览可以用 requestAnimationFrame，但渲染出的内容仍以同一时间轴计算。

对真实 Boids 等依赖历史状态的部分，先用固定步长计算整段运动并保存每个采样时刻的稳定 ID、位置、速度、朝向、振翅相位和主角生命状态。必要时保存 90 秒端点状态用于插值，它不算额外输出帧。四个 worker 读取同一状态缓存，不从各自区间独立启动模拟。

相机使用连续平移与对数尺度插值，跨镜接缝继承前一镜的坐标、大小和速度；用插值切线控制连续性，不在每个镜头边界重新减速、加速。动作、相机和音频 cue 分开编排，共用同一个秒数来源。

## 4. 画面、锚点与几何约束

背景 #F4F2EC，黑色主体 #101010，灰色云和远景 #C8C5BD。黑白剪影，稳定锐利边缘，纸纹轻微且固定。视觉重点位于 y<918；双语字幕在 y=930–1048 左右。

**鸟：**正式素材画布 1024×640，身体轴心 (540,328)，胸腔中心 (595,330)，胸腔椭圆半径 (62,40)。鸟、胸腔遮罩和细胞纹理共用父级空间。世界到屏幕可写为 `screen = anchor + scale × R(angle) × (local − pivot)`。不能分别对不同姿态按非透明包围盒重居中。

揭晓后鸟的实际轮廓宽约画面宽度 1/3；计算实际黑色边界，不直接将 1024 像素整画布当作鸟宽。S02 构图参考中鸟位于中央偏右，建议身体轴心落在约 (1090,480)，微调时保证胸腔可读。

**城市：**道路、建筑均为 3200×2400，主路口 (1600,1200)。近景参考对应 `screen = 2.2 × world + (-2432,-2019)`，因此主路口落在 (1088,621)。可以使用这个精确变换匹配参考图；若换相机构图，必须同步更新所有城市图层和角色。`layout.json` 的近景相机建议与参考图裁剪并不完全相同，不能混用两套变换。

从近景拉远时，比例由约 2.2 降到约 0.45，主路口屏幕锚点平滑移向约 (960,480)。角色位置先在城市世界坐标里计算，再应用相机变换。

**地球：**1140×1140，中心 (570,570)，外部透明，海洋黑色、大陆暖白。最终屏幕中心约 (960,480)，直径约 540。只有单张平面素材，默认静止；若做小幅整体转动，应清楚是平面图形转动。真实自转需另做球面纹理，不横向拉伸大陆。

## 5. 逐镜动画指令：直接落实到关键帧

### S01｜0–6 秒：黑屏进入微观

**参考与图层：** `composition/S01_layout.png`、`background/ivory`、`micro/tissue`。这是抽象组织剪影，与原游戏录屏区分。

0–0.8 秒保持黑屏。0.8–2 秒整个暖白组织画面一起淡入，避免先亮白底再突然贴细胞。2–6 秒镜头持续缓慢拉远，细胞有极轻、错开相位的局部脉动。视觉锚点中央偏右，周边组织超出画幅，使观众尚不能判断全貌。

在工程中从第一镜就定义该区域属于鸟胸腔，而不是第六秒突然把一整屏细胞贴到鸟图上。微观纹理在 S01/S02 交界保持尺寸、位置与运动连续。末帧不切黑、不停住。低频约 2 秒进入，无旁白、无字幕。

### S02｜6–18 秒：微观世界属于一只鸟

**参考与图层：** `composition/S02_layout.png`、`bird/bird_a_*`、`bird/chest_mask`、`micro/tissue`。

6–9 秒保持拉远，先见胸腔边缘，身体其他部位仍部分超出画面。9–13 秒继续拉远，头、尾与翼根进入，13 秒附近认出完整鸟形。具体比例通过查看轮廓调整，让“先看见组织、后认出宿主”成立。

用离屏 Canvas 将组织裁剪进胸腔椭圆，微观纹理窗口先保留可见。鸟形认出后再于 14–15 秒把胸腔窗口平滑合拢成纯黑实体；不能在认出鸟前抹掉细胞关联。

13–15 秒相机短暂同速跟拍，鸟身体轴心约 (1090,480)，朝右。15–18 秒先有正常振翅，再出现更弱的振翅，身体稍下沉，但仍活着。振翅以稳定 body 为基础控制两翼，保持身体不漂移；翼形插值须有同拓扑路径，不能对不同命令数量的 SVG 字符串直接插值。

首段配音初排 9.5–16.5 秒，字幕分两屏。鸟完整识别后约 0.3–0.5 秒触发第一次音乐扩张。18 秒前先定义下一镜主角的群体位置，保证拉远之后它确实属于近群下缘。

### S03｜18–34 秒：两种鸟群运动

**参考：** `composition/S03_layout.png`。远群在上，稀疏长带；近群在下，较密集且可辨个体。中央留明显空白。

18–22 秒延续单鸟拉远，其他鸟因视野扩大从画面边缘进入。主角使用稳定 ID，不通过新建另一只鸟来替换。远群可从约 24–36 只起步，近群约 60–100 只，按实际可辨度调整。群体构图参考提供形态，不要求死板复刻每只鸟的位置。

22–27 秒远群前缘先转向，附近鸟响应，再逐步影响后方。27–32 秒近群收拢、弯曲、展开。32–34 秒相机接近静止，给群体运动两秒观看时间。

采用真实局部分离、对齐、聚合规则时，先固定种子预计算；边界/引导力适量维持画面调度，但不能让整群作为一张图片整体旋转。每只鸟独立振翅相位，约 2–3.5 Hz 的初始频率可按视觉调整，个体有轻微差异。主角在近群下缘可追踪，不画彩色轮廓。

鸟死亡前如果已有身体下沉，它的异常可以逐渐加强，但36秒前仍允许主动振翅。20–33.5 秒旁白讲局部规则与涌现，音乐逐层积累。S04 原样接续布局，不重新随机生成。

### S04｜34–45 秒：个体离开，群体继续

**参考：** `composition/S04_layout.png`；它是离群后的某一构图，不能在34秒硬切成这张图。

34–36 秒主角沿群体下缘失速，最后一次振翅幅度明显减小。约36秒切换为 slack 状态，停止主动振翅。36–39 秒相机保持，让近群向右上继续、主角向右下坠落同时可见。原来邻近的鸟局部调整间距，填补空缺，群体照常前进。

39–45 秒相机才逐步向下追踪。坠落路径使用位置与速度连续的曲线或积分结果，39秒不把鸟瞬移到画面中央。死亡后的角度只轻微被动摆动，例如围绕下坠方向小幅偏转；没有主动扑翼或翻滚表演。

约36秒音乐抽掉音型和多数上层，保留低音尾音与风声，形成0.6–1秒织体缺口。36.5秒开始死亡旁白，两句间保留停顿。45秒交界继承同一死鸟、位置、角度、速度和相机。

### S05｜45–59 秒：云层里的隐藏剪接

**参考：** `composition/S05_layout.png`、三条 `cloud/cloud_band_*`、`city/roofline_transition`、城市分层。

45–49 秒继续下追死鸟，鸟在中央偏下但高于字幕区。相机向下，静止世界的云与屋顶在画面内向上经过。云只叠加少量横向自然漂移，不反向全部向下运动。

49–52 秒云渐渐遮住鸟。三条云带有透明边缘，单条覆盖不能保证完整遮挡；叠加、扩大并增加同色遮罩，在约51.5–52秒确保全画面覆盖至少6–12帧。完整遮挡期间移除鸟、切换城市背景，不能透过透明孔洞看见切图。

52–56 秒城市屋顶侧影由下向上进入，浅灰远景先出现、黑色近景随后。56–59秒借仍在移动的云再隐藏一次图形视角切换，转入同一城市的路口俯视图。屋顶侧影和道路俯视不是同一物理视角，不把楼体压扁来伪造连续三维相机。

59秒相机已经落到路口近景规定变换，S06直接接续。声音从风声过渡到城市低强度环境声，53秒音乐低位重启，56–59秒一句旁白。鸟离开后不再出现。

### S06｜59–76 秒：先看清人，再看清城市

**参考：** `composition/S06_layout.png`、`city/intersection_reference`、城市分层、车辆、两个行人姿态、`layout.json` 路径。

59–63秒保持路口近景。先让一辆车在斑马线前减速停住，行人穿过对应横道，车随后重新行驶；另外两人从街角不同位置会合，停一拍后并排行走；另一辆车稍晚进入路口，沿圆滑路径转入支路。动作错开，4秒内建立过程，允许部分动作在相机升高后继续。

路径按已有世界坐标校验斑马线与道路。一旦路径与素材道路不吻合，以实际道路修正路线并记录变更。车辆按曲线切线旋转，行人两种姿态错相交替；所有对象共享相机变换，不能按屏幕坐标走路再独立缩放。

63–72秒相机升高，比例约2.2连续降到0.45附近，主路口屏幕锚点逐渐由(1088,621)移动到(960,480)。72–76秒拉远速度减小，保留更多路口和缓慢流动。人和车随比例变小，远处人物可以简化为点，城区几何稳定。

建筑、道路、角色的父级变换完全一致。只用正式道路＋建筑绘制城市；`city_master`和`intersection_reference`用于检查，不再叠上第二套几何造成重影。环境声随升高退去，配乐持续增强，旁白仍清楚。

### S07｜76–87 秒：由一个路口走到地球

**参考：** `composition/S07_layout.png`、城市分层、`earth/earth_reference`、`earth/planet_disc`。

76–79秒沿用城市末尾相机继续拉远，路口仍可追踪。79–81秒把城市区域缩至地球参考里一个大陆上的固定锚点，露出大陆局部与弧面。制作前在实际地球图上选一个大陆内部点，记录归一化坐标，不能随镜头随机换点。

图形过渡用城市缩放、局部地球图、大陆与圆形遮罩共同完成。相机以同一个大陆锚点拉远，81–83秒完整地球进入并落在(960,480)、直径约540的位置。让锚点在拉远中自然移动，而不是图中城市消失后突然在别处出现一个球。

83–87秒相机稳定，地球默认静止，纸纹不闪烁。单张地图不制作横向拉伸的假自转。地球细节与参考保持一致，外部透明部分不错误填成黑色方块。

79.5–80.5秒收薄音乐，实际地球可认出后约0.3秒开始全片最大和声扩张。最后一句在77–85.5秒附近，尽量在“civilizations”结束后让音乐达到最饱满状态。最大峰值有空间，避免遮住低沉旁白。

### S08｜87–90 秒：标题与余韵

沿用S07画面、位置、比例，87秒不重建地球。87–88秒淡入标题，英文EMERGENCE在上、中文涌现在下。中心x=960，英文基线约817、中文约873，两行都高于y=918。88–90秒保持，无旁白，音乐尾音平顺收束。

最后输出帧2159保持地球与完整标题，由接入方决定下一界面过渡。片内不额外加两秒黑屏，不增减总帧数。

## 6. 英文旁白与双语字幕

只生成英文语音。成熟到年长的低沉男声，自然胸腔共鸣、轻微岁月感、纪录片观察语气，约105–115词/分钟。死亡句平静，最后一句有克制的敬畏。避免预告片吼声和故意拉长每一个词。

配音以句子为制作单位；不是按字幕换屏把连续句截断。初排窗口：

| 时间 | 英文配音 | 中文字幕 |
|---|---|---|
| 9.5–16.5 | Within this bird, an unseen world was changing. A small infection spread. | 在这只鸟的体内，一个看不见的世界正在改变。一场微小的感染扩散开来。 |
| 20–23 | Each bird follows its neighbours. | 每只鸟跟随着附近的同伴。 |
| 23–29 | Keeping distance. Turning together. Staying close. | 保持距离。一同转向。留在群体附近。 |
| 29–33.5 | From these small actions, order emerges. | 秩序，从这些微小的行动中涌现。 |
| 36.5–41 | This bird died of acute pneumonia. | 这只鸟死于急性肺炎。 |
| 41.5–45 | The flock continued its flight. | 鸟群仍在继续飞行。 |
| 56–59 | Below, another world moves. | 在下方，另一个世界也在运行。 |
| 60–65 | People meet, exchange, cooperate, and compete. | 人们相遇、交换、合作与竞争。 |
| 66–75 | Their lives intertwine, shaping a society no one person could create alone. | 他们的生活彼此交织，形成任何一个人都无法独自创造的社会。 |
| 77–85.5 | Across generations, these connections grow into cities, cultures, and civilizations. | 世代之间，这些联系逐渐形成城市、文化与文明。 |

先生成正式声音，再测每句真实时长，按实际语音校准`timeline.json`中的字幕。已有draft字幕可直接用于预演，但最终不能声称它已对齐不存在的配音。不严重拉伸语音去强塞暂定窗口；优先调整句内停顿和镜头内部动作，保持90秒主结构。

中文约40px、英文约28px，居中，中文在上。使用实际加载并检查的字体，`document.fonts.ready`后再渲染。底部字幕板应在城市黑路背景上也可读。长句按语义拆屏，字体不要越挤越小。

标题不是朗读文本，也不是旁白SRT的一条cue。中文字幕、英文字幕、配音共用一份文本数据，更新一次后同步导出。

## 7. BGM与声音制作

创作一条90秒原创器乐配乐。约64 BPM，核心管风琴音色、低频持续音、缓慢弦乐铺底和简短重复动机。参考《星际穿越》带来的宇宙尺度、未知揭晓与敬畏感，以原创主题实现。

| 时段 | 声音动作 |
|---|---|
| 0–2 | 给黑屏和淡入空间，安静。 |
| 2–6 | 极轻、窄音域低频进入。 |
| 6–13 | 管风琴低音扩展，和声悬而未决。 |
| 13.3–15 | 第一峰值，鸟先被识别，音乐随后打开音域。 |
| 18–34 | 音型与弦乐累积，低于地球段。 |
| 36–37 | 抽去音型与多数上层，保留低音尾音和风。 |
| 37–53 | 稀薄，为死亡和坠落留空间。 |
| 53–59 | 管风琴低位重启，风声融入城市声。 |
| 59–79.5 | 音型返回、弦乐层叠，随城市升高推进。 |
| 79.5–80.5 | 收薄，制造最后揭晓前的呼吸。 |
| 81.3–85.5 | 地球识别后释放最宽阔和声，配音结束附近达到最大。 |
| 85.5–90 | 撤音型，尾音逐步收束，无硬切。 |

没有可用音乐生成服务时，用音源或程序合成实际制作WAV；普通振荡器可以做预演，但需标明音色局限。最终试听必须检查管风琴高声部是否刺耳、低频是否遮住男声、死亡处缺口是否清楚、地球处是否真正形成和声释放。不要仅堆响度替代递进。

音乐、人声、环境声分别输出90秒、48kHz时间对齐音轨，每声道4,320,000采样；一句旁白的短文件也可以保留，同时提供从t=0对齐的完整旁白轨。每帧恰好对应2000个音频采样，保持固定时基。

最终混音使用实际测量的响度/峰值数据，可参考约−14 LUFS、真峰值≤−1 dBTP；仅有采样峰值测量时，不宣称测得真峰值。配音出现时适度压低BGM并避让低中频。先混成一条完整WAV，再与最终视频统一封装，避免四段音频各自编码引入接缝。

## 8. 四并发：共享动画，分段渲染与编码

四并发指最多四个本地渲染/编码worker。先完成共享素材加载、时间轴冻结和状态预计算，再分配区间，不让四个人或进程各自创作四段不同风格的视频。

| Worker | 输出帧区间 | 帧数 | 时间区间 |
|---|---|---:|---|
| W0 | [0,540) | 540 | [0,22.5) 秒 |
| W1 | [540,1080) | 540 | [22.5,45) 秒 |
| W2 | [1080,1620) | 540 | [45,67.5) 秒 |
| W3 | [1620,2160) | 540 | [67.5,90) 秒 |

四个worker加载同一版本源工程、字体、图层、运动状态。独立输出目录，使用全局帧号命名，例如`frame_000000.png`。每个worker必须能直接渲染任意全局帧。各分段边界可能位于镜头中间，所以尤其不能重启Boids模拟、字幕、翼相位或相机。

若有运动模糊，先默认关闭；需要开启时对固定时间点做可复现子采样，worker拥有边缘采样数据，但最终只输出各自区间，避免重复帧。

先以低分辨率验证完整90秒预演和代表性帧，再渲染2160帧全分辨率。使用受控队列并检查CPU/RAM/磁盘，避免四个worker中每个FFmpeg又自动占用全部逻辑核心。

“绑核”按操作系统实现：

- Linux且实际安装`taskset`时，可为四个worker分配允许使用的不同CPU集合。先读取有效cpuset与CPU拓扑，不硬写0–3为必然可用。两级线程数（浏览器进程与FFmpeg）都要控制。
- Windows不使用Linux的`taskset`。可用PowerShell启动隐藏子进程，并给实际渲染/编码进程设置`ProcessorAffinity`；Chromium可能有多个子进程，必须验证限制是否覆盖实际工作进程。也可以先限制FFmpeg线程并实测四并发，绑核不是完成影片的前置条件。
- 少于四个可用核心或内存不足时，最多四worker但降低实际同时数量，并报告资源约束，不擅自改变帧数或画面质量。

CPU集合应避开重叠、尽量按实际物理核心分组；具体编号由当前机器测得。绑定不是通用性能保证，短样本比较后选择有效方案。

PNG编码使用固定24fps输入；四段编码参数完全一致：1920×1080、相同帧率、H.264编码、相同像素格式与时间基。一般交付`yuv420p`、合理CRF质量与`+faststart`。先输出无音视频分段，成功后按顺序拼接；无法无损拼接时再一次性编码完整帧序列。最终只封装一次完整音轨。

每段失败可从缺失全局帧继续渲染；不删除全部已成功帧重新开始。输出完成后检查编号连续、2160帧无缺失重复；使用ffprobe检查实际帧数、24fps、90秒时间轴和音频同步，不仅根据文件名判断成功。

## 9. 预览、检查与交付

先形成完整可播放预演，然后检查5–15秒、33–59秒、73–90秒三个长连接，再导出最终版。查看代表帧：0、19、48、144、312、360、432、815、816、864、936、1079、1080、1236、1248、1415、1416、1512、1620、1823、1824、1944、1992、2087、2088、2159。代表帧只能检查构图，仍需实际播放检查速度、运动与声音。

检查四worker接缝：539/540、1079/1080、1619/1620。按同一源工程顺序渲染这些帧，比较并行输出是否一致。清楚区分自然运动差异和重置造成的跳变。

重点验收：

- 组织与胸腔注册准确，13秒附近鸟身份揭晓清楚。
- 鸟身体与翼根连续，振翅没有双轮廓，36秒后不再主动振翅。
- 两个鸟群独立形态、振翅错相、局部转向，主角ID不中断。
- 云在换场时完整遮挡，屋顶与路口隐藏切换，静止世界经过方向正确。
- 城市共用几何与相机，路口至少看清一次让行与会合。
- 城市锚点连续进入大陆与地球，地球没有伪自转拉扯。
- 两次音乐峰值有层次，死亡处有缺口，英文男声可懂，最后留白完整。
- 2160帧、90秒、字体与字幕无错误，视频音频时基一致，尾音无截断。

交付：完整双语字幕MP4、无字幕MP4、独立SRT/VTT、英文旁白WAV、音乐WAV、环境声WAV、可取得的配乐分轨、完整源工程、依赖与版本、四并发命令和实际平台绑核/线程设置、ffprobe与渲染检查结果。若某个音轨实际未生成，明确标记，不以静音文件冒充正式配音。

在TapTap Maker项目内执行时，遵循AGENTS.md及具体工具schema。额外视频服务的收费确认与声音试听选择按项目规定处理；本提示词中的建议不能代替所需确认。不要因本片制作自行构建、提交或切换服务环境。最终报告清楚区分：已生成、已播放检查、已编码、待补内容。

从检查素材和工具开始，完成现有条件下的工作。最终成果应是有连续动作、镜头调度、声音递进和双语字幕的90秒影片。
