# 手机布局调整与电脑验证

2026-10-19，基于用户提供的 2400×1080 横屏手机截图调整。本文记录本地验证阶段；提交、远端构建与正式发布状态以 Maker 返回结果为准。

## 布局

- 开始菜单：手机或矮窗口使用紧凑标题、开始按钮、无尽模式，以及并排的设定/制作名单/退出，全部在一屏内。Web 首次触摸前也按可用高度适配。
- 游玩：左下摇杆；右下吸附主按钮，周围为分离、切群、技能，以及解锁后的冲刺/诱饵圆形按钮。地图、暂停、群组入口放在右上安全区内。
- 任务：默认显示阶段、当前进度与细进度条；点“详情”展开目标与提示。常驻操作说明取消，仅短暂显示操作反馈。
- 教程：窄提示卡放在上方中间，“继续”和“长按跳过”并排。选卡、卡牌说明、技能菜单或暂停菜单出现时，教程让出前景，不修改教程进度。
- 原生控件按创建时保存的 `id` 查找。修正菜单只在创建后写 `props.id` 的问题，使布局和自动化能找到真实按钮。

主要文件为 `scripts/UI/MainMenu.lua`、`HUD.lua`、`SkillPanel.lua`、`TutorialOverlay.lua`。桌面常规布局和玩法判定继续使用现有实现。

## 在电脑上打开手机布局

双击根目录 **手机布局测试.cmd**。它在真实 UrhoXRuntime 中以 844×390 打开手机布局，鼠标模拟触摸；从正常菜单开始，可以点按钮、拖动摇杆。约 100 秒后截图并退出，完整证据在 `validation/mobile-layout-20261019/interactive/<run-id>/`。启动或资源准备占用额外时间。

自定义比例、测试场景或延后退出可在项目根运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local-preview/Test-MobileLayout.ps1 -Case interactive -Width 960 -Height 432 -ScreenshotFrame 10000
```

脚本使用已安装的 Maker CLI，临时生成独立测试入口，结束后删除该入口；不改发布入口、项目窗口配置、服务环境或全局 PATH。普通预览还在运行时会拒绝启动；另一个验证任务占用通道时应排队，不强杀进程或手删锁。

| Case | 行为 |
| --- | --- |
| interactive | 正常菜单、教程与操作；不自动开始、不赠送技能 |
| menu | 只截开始菜单，默认第 240 帧 |
| tutorial | 经正常菜单回调入场，保留开场教程 |
| hud | 正常入场后用测试代码结束教程并解锁冲刺/诱饵，用于检查全部按钮 |
| skills | 与 hud 相同，再打开功能菜单 |
| cards | 正常入场后注入正式选卡，并保留活动教程以检查遮挡冲突 |

后三类是受控布局状态，不是自然通关或自然获得卡牌的证据。自动截图状态会仅为测试实例解除失焦限制，以便后台窗口也能展示指定面板；interactive 模式与发布入口保留正常失焦暂停。默认第 2400 帧截图；若图中仍在加载或转场，应根据日志选择更晚帧，不把运行报告 PASS 当布局通过。

## 验证边界

本机使用原生 Yoga/NanoVG 和实际资源渲染；测试入口复用 main 的菜单预加载、入场和更新生命周期，不用浏览器 HTML 仿制游戏。正常 HUD 的原生布局断言检查了操作按钮边界和相互重叠。

电脑窗口尺寸不自动模拟手机 DPR、刘海、平台胶囊菜单、系统手势、多指手感、移动 GPU 性能或解码差异。当前窗口启用触摸模拟和游戏的触屏分支；仍需要用户在原手机上复测。

逻辑回归：菜单 15 项、教程 20 项、选卡 5 项、新增手机交互 2 项通过。`compact_ui_regression.py` 为 10/11：结局视频测试替身缺少 `Seek`；用未修改的 HEAD HUD 重跑同一测试可复现，记录在 `validation/mobile-layout-20261019/compact-baseline.txt`，本轮未修改结局视频。
