# 游戏设计文档

## 1. 项目定位

本项目是一款 2D 俯视视角的多尺度病毒涌现模拟游戏。玩家控制流感病毒群体的行为倾向，观察病毒与细胞、免疫系统相互作用，并通过鼠标滚轮在小鼠个体、组织和细胞三个尺度之间切换。

游戏的核心主题是“涌现”：玩家不能直接指定某个细胞感染或决定小鼠死亡，而是改变病毒群体的局部行为。感染范围、免疫反应、组织损伤和小鼠结局由模拟规则共同产生。

本项目以 6 人、18 天为开发约束，目标是一局约 5～8 分钟、具有完整起点和结局的可玩原型，而非科研级病程预测工具。

## 2. 核心体验

玩家应当能够看到一条连续的因果链：

> 改变病毒群体策略 → 病毒分布与感染速度变化 → 免疫系统响应 → 组织状态变化 → 小鼠出现症状 → 康复或死亡

细胞层面的事件不是独立演出。玩家看到的病毒移动、细胞感染和免疫清除，都应对应同一套病程数据。

## 3. 玩家控制什么

玩家控制的是病毒群体的策略，不是逐个指挥病毒颗粒。病毒个体根据当前位置、周围细胞、局部病毒浓度和免疫压力自行行动。

原型保留三种主动策略：

| 策略 | 玩家意图 | 收益 | 代价 |
|---|---|---|---|
| 聚集 | 提高选定区域的病毒浓度 | 更容易形成局部感染点 | 更容易引发集中免疫响应 |
| 扩增 | 提高感染细胞释放病毒的速度 | 病毒数量增长更快 | 细胞损伤及免疫信号增加 |
| 隐匿 | 降低病毒活动和免疫可见度 | 减缓局部清除 | 复制与扩散速度下降 |

玩家可选择一个组织区域作为策略作用范围。这里的“选择区域”是游戏化的群体行为控制，不表示真实病毒能自主判断方向或执行命令。

变异、复杂遗传算法和更多病毒能力不作为首版必需内容。只有核心循环稳定后，才考虑加入一次带收益与代价的简单变异选择。

## 4. 三个观察尺度

### 小鼠个体层

展示小鼠的整体病程及结局，包括活动状态、鼻部分泌物、呼吸状态和虚弱程度。界面以少量状态指标辅助观察，例如病毒载量、炎症、组织损伤和整体健康。

这一层用于观察微观变化造成的宏观结果，不承担精细病毒操作。

### 组织层

展示一小片呼吸道组织中的感染分布、局部损伤和免疫响应。玩家在这一层选择策略作用区域，观察病毒群是否形成感染点，以及感染是否向邻近区域扩展。

首版只模拟有限的几个相邻区域，不制作完整呼吸道地图或多个器官。

### 细胞层

展示当前组织区域内的少量细胞、细小病毒颗粒及免疫细胞。可观察到病毒接近并附着细胞、细胞进入感染状态、病毒从感染细胞释放，以及免疫细胞清除病毒或感染细胞。

这一层是游戏的主要视觉体验，但屏幕上的每个病毒颗粒不必对应后台的一个真实病毒计数单位。

## 5. 鼠标滚轮与镜头

- 滚轮向上：逐步放大；到达阈值后进入更微观的视图。
- 滚轮向下：逐步缩小；到达阈值后返回上一尺度。
- 跨尺度时保留当前选中的组织区域，并读取同一份模拟状态。
- 使用短暂的镜头过渡连接视图，但不要求实现物理上连续、无限放大的地图。
- 玩家在细胞层返回组织层后，应能认出刚才观察的感染区域。

三个尺度可以由独立场景或画布实现，重点是状态和位置关系保持一致。

## 6. 最小模拟规则

首版后台以“组织区域”为计算单位，当前细胞视图只展开少量可见对象。

每个组织区域至少记录：

- 易感细胞数量
- 感染细胞数量
- 死亡细胞数量
- 病毒浓度
- 炎症水平
- 组织损伤
- 免疫压力

病毒群至少记录：

- 附着能力
- 复制倾向
- 免疫可见度
- 当前策略
- 所在区域及局部分布

规则应体现以下关系：

1. 局部病毒浓度越高，易感细胞被感染的机会越大。
2. 感染细胞经过一段时间后释放新病毒；流感病毒不是通过自身分裂繁殖。
3. 感染和细胞死亡提高炎症信号。
4. 免疫响应存在延迟；免疫压力升高后，病毒更容易被清除。
5. 过强的感染和炎症都可能增加组织损伤。
6. 病毒量下降后，小鼠症状和组织损伤不会立即清零。
7. 小鼠的症状由病毒载量、炎症和组织损伤共同决定。

这些是用于游戏的简化关系，不用于预测真实小鼠的实验结果。

## 7. 首版对象

| 对象 | 游戏中的作用 |
|---|---|
| 呼吸道组织细胞 | 被感染、受损、死亡或维持健康 |
| 流感病毒群 | 在局部区域扩散，由感染细胞产生新病毒 |
| 巨噬细胞 | 清除部分游离病毒及细胞碎片 |
| 杀伤性 T 细胞 | 清除被识别的感染细胞 |
| 小鼠 | 显示整个感染过程的宏观结果 |

T 细胞主要作用于感染细胞，不表现为直接吞噬大量游离病毒。

## 8. 一局游戏

一局从少量病毒进入局部组织开始：

1. 病毒接触并感染最初的细胞。
2. 玩家选择聚集、扩增或隐匿策略。
3. 新病毒释放，感染向邻近位置发展。
4. 炎症增强，免疫细胞逐渐进入。
5. 玩家根据局部形势调整策略。
6. 病毒被压制，或组织持续受损。
7. 小鼠康复或死亡，游戏展示造成该结局的主要状态变化。

首版必须能稳定触发康复和死亡两种结局。重症可以作为过程状态，不必制作第三套独立结局流程。

## 9. 六人分工

| 人员 | 主要职责 |
|---|---|
| 程序 A／技术负责人 | 模拟主循环、共享状态、结局判定、版本整合 |
| 程序 B | 三尺度场景、滚轮镜头、区域定位与交互 |
| 程序 C | 细胞和病毒的可视化行为、免疫事件、策略操作 |
| 美术 A | 小鼠与组织层画面、场景资源 |
| 美术 B／UI | 细胞层资产、状态效果、界面 |
| 策划／测试 | 数值表、病程节奏、验收、音效整理与打包测试 |

所有成员在第 2 天前统一引擎版本、目标分辨率、资源尺寸、命名方式和共享数据字段。程序先使用占位素材开发，不等待正式美术完成。

## 10. 18 天排期

| 时间 | 交付目标 |
|---|---|
| 第 1～2 天 | 确定范围、状态字段、视觉参考和工程规范 |
| 第 3～5 天 | 占位素材跑通三个尺度、滚轮切换、病程推进和两种结局 |
| 第 6～9 天 | 实现感染、复制、免疫响应及三种玩家策略 |
| 第 10～12 天 | 接入正式画面、小鼠症状及关键事件动画 |
| 第 13～15 天 | 调整数值、完善反馈、修复阻断问题 |
| 第 16～18 天 | 测试、优化、打包与演示准备，不再增加大功能 |

第 5 天为范围检查点：如果三尺度流程尚未跑通，则将组织层收缩为简化的区域选择视图，优先保住小鼠层、细胞层和完整结局。

## 11. 不做的内容

首版不做完整小鼠体内地图、多器官病程、真实病毒基因组模拟、复杂变异树、完整适应性免疫系统、逐个模拟全部病毒、联机，以及科研级病程预测。

## 12. 验收标准

- 一局可以从最初感染推进到康复或死亡。
- 滚轮能够在三个尺度之间往返，状态不重置。
- 玩家选择不同策略后，病毒分布或病程产生可观察的差异。
- 细胞层事件与组织层、小鼠层的状态一致。
- 玩家能够理解“病毒行为如何逐层影响小鼠”，而不只是观看预设动画。
