# 本地启动器修复（2026-10-17）

用户截图中的失败发生在 ProjectBuilder 生成 manifest 前，Runtime 尚未启动，不是新增细胞动画的 Lua 运行错误。

## 已确认的问题与修复

1. `start-game.ps1` 优先固定调用仍存在的 Maker 0.0.36，未跟随已经安装并配置的 0.0.37。改为从已安装稳定版本中选择最新版本，不联网下载 CLI。
2. 上次启动失败时 `preview status` 返回非零且 `ok=false`。旧启动器先抛错，用户再次双击也无法重试。现在先解析状态，仅在确认 `state=failed`、`process_alive=false`、Runtime 已安装时允许重新启动，其他错误继续保留。
3. 旧控制台仍在运行，新 CLI 按版本身份保护规则拒绝接管。已获得用户明确许可，使用官方 stop 流程停止旧控制台并切到 0.0.37；遇到活动准备任务时先用官方 `preview stop` 取消，没有按进程名强杀。
4. 本机官方资源 CDN 的 IPv6 连接超时。实测 IPv6 TCP 两秒超时，IPv4 TCP 约 0.006 秒成功；同一 HTTPS 索引默认地址顺序约 30.16 秒，优先 IPv4 后约 0.09 秒。Builder 多次串行下载导致累积等待，超过准备预算。
5. 用户再次启动报告 `spawn git ENOENT`。重新构造桌面实际使用的 Machine + User PATH 后确认：桌面没有 `git.exe`，此前 Codex 环境注入了 Git 路径，首轮验证遗漏了这一差异。启动器现在依次查找指定 Git、PATH、常用安装目录及已安装的 Codex Git，验证 `git --version`，把绝对路径传给 Maker 支持的 `TAPTAP_MAKER_GIT_BIN`，并仅在启动器进程及其子进程的 PATH 中加入 Git 目录，不修改系统或用户 PATH。

`启动游戏.cmd` 也会保存 PowerShell 返回码，在暂停后仍正确返回失败，避免外层检查误以为启动成功。Maker 错误优先显示具体原因，不再默认输出整段 JSON。

网络修正位于 `local-preview/python/sitecustomize.py`，仅对 `tapcode-sce.spark.xd.com` 的未指定地址族查询把 IPv4 排在前面，保留 IPv6 回退、原 DNS 地址、TLS 证书与主机名验证。其他域名、显式 IPv6 请求和系统网络设置不变。

启动器通过 Python 自带 venv/ensurepip 离线创建项目内 `.preview-python`，将此模块放入该隔离环境，并通过 Maker 正式支持的 `TAPTAP_MAKER_PYTHON_BIN` 传给控制台。没有修改 Maker 包、全局 Python、用户级 MCP 配置或服务环境。环境和 Python 缓存已忽略，不作为游戏资源打包。首次创建需要几秒；缺失 pip 的中断环境会继续补齐。

单独设置 `PYTHONPATH` 的初始方案未保留：Maker 的后台环境白名单不会传递它。最终方案使用白名单支持的 Python 解释器入口。
